## 1. ゲーム全体の概要

### 1-1. 何が遊べるか
- 14モード（R1〜R11、C1〜C3）を独立したメニュー入口として持つ。【事実】実際にプレイ可能なのは**R7とR8（第1章）のみ**。残りは「未実装」で開始ボタンなし（REQUIREMENTS REQ-MODE-02）。
- R7は「配属先は、明日変わる」。新人駅員が青嶺中央駅（架空の青嶺広域鉄道）に配属され、評価・資格・異動で職を変えていく社員生活ドラマ。仕様は8シーズン×12章（96章）を目標にするが、実装は第1〜10章（約1,824ノード）。進捗は全体の1%程度とPROGRESS.mdに明記。
- 画面は3D（歩行できる駅）／擬似3D／2D（ピクセル調の会話）。会話は2D中心。構成は ui → controller → engine（純ロジック）→ render。物語は `scripts/build-story.mjs` と `scripts/story/ch*.mjs` が原本で、`story.json` を生成。

### 1-2. プレイの1サイクル（R7第1章の例）
```
[2D 面談/会話] → [3D ハブ：駅を歩く]
                    │ 歩いて人物・設備に近づく →「調べる」
                    ├─ 業務(ミニゲーム) → 0〜100点 → good/mid/bad の講評 → 評価点(eval)加減 → ハブへ
                    ├─ 依頼(会話＋選択) → 先輩の講評 → フラグ/関係値 → ハブへ
                    └─ 時刻イベント（10:40遅延・12:00昼・14:00・17:00）が強制で割り込む
                  ↓ 時刻 or 「勤務を終える」
[2D 終業面談] → 重要選択（週末の過ごし方）→ エピローグ → 章末（評価・経歴・年表に保存）→ 次章
```
- 評価（eval）は章をまたぐ数値で、第6章の面談などで進路の可否に使われる（condition `eval` が52箇所）。
- 重要選択は章あたり約1〜4個（仕様は1〜3）。仕様第13章の「過去の選択の後効き」を、`legacy.*`/`route.*` フラグで実装している。

### 2-4. 重要選択の評価
凡例：【ジレンマ度】低/中/高、【合流】選択直後から共通ノードまでの最短距離。

**(1) ch1.p_wish「三年後、どんな仕事を？」**
- ジレンマ度：低。4択どれも森下が肯定する（「いい答えです」）。誤った答えがない＝選ぶ重みがない。
- 後効き：`wish_station/depot/planning` は各1回読まれる（終業の白石の一言のみ）。`wish_open` は未読。合流1。
- 問題：プレイヤーが**実際に興味のある部署を選ぶだけのアンケート**で、嘘もリスクも利得もない。

**(2) ch1.delay_choice（時限25秒）★章の最良場面**
- 選択肢：確認してから／「たぶん間に合う」／久保田に確認依頼。
- 正解が見え見え：直前に久保田が「確定と見込みを分けて読む」と教えており、「たぶん」は誤答の合図。選択肢の `tone` も risky/careful/neutral とデータ上ラベル化されている（画面に出ているかは UNVERIFIED。出ていれば完全なネタバレ）。
- 時限の既定は `ask`（無難な選択）：**時間切れが罰にならない**。時限なのに制限時間が緊張を作れていない。
- 良い点：誤答ルートの帰結が具体的（旅行客が乗換えに失敗して戻ってくる、「たぶんと言われたから信じたのに」）。**認める／責任転嫁／黙る**の第2選択が本物の人間ドラマで、`legacy.concealed` が第2・9・10章に読まれる（5読み）。この構造を全選択に広げるのが改善の核心。
- 合流：3ノード（最長）。

**(3) ch1.route_choice 午後の持ち場（接客/ホーム/事務）**
- ジレンマ度：中。能力/関係の選好選択で、3択に優劣がない点は良い。
- 後効き：最も強い。`route.*` が第2・3章の場面・ミニゲーム・人物を分ける（読み9/14/9）。**唯一「別の内容を遊ぶ」分岐**。
- 問題：選んだ後の差は「その持ち場の専用イベント1つ」。ホームのみ重い場面（線路）があり、接客・事務は軽い。難度・緊張が持ち場間で不均等。

**(4) ch1.closing_choice 週末（久保田の練習/山科の基地見学/休む）**
- ジレンマ度：中。他者の期待に引き裂かれる良い設計（久保田 vs 山科）。選ばなかった側には軽い反応しかなく、**捨てたものの痛み（損失）がない**。
- 後効き：`mentor_line`・`depot_tour` 各1読み、`rested` は未読。合流4（唯一長い）。
- 問題：休むが無害で最も安全。「睡眠を取る＝正解」が直後の第3章前夜でも繰り返される。

**(5) 大量の非重要選択（約20個）**：忘れ物、迷子、財布、電話、案内……すべて「丁寧に記録（honest）／軽く済ませる（quick）／危ない近道（risky）」の同型3択。【事実】`vend_report`/`lost`/`assist`/`child`/`shop`/`guide`/`stroller`/`board_c1` はフラグも後続条件もなし、効果は eval と rel のみ。後の場面がまったく変わらない。【推測】3択が毎回「模範解答・平凡・危険」に整列しているため、数回で選択の意味を覚えて、思考せずに最上段を選ぶ。

### 2-5. 業務（ミニゲーム）
- 種類は10形式（checklist 6、find 4、compose 2、timing 2、sort 2、route 2、roster/terminal/memory/watch 各1）と**多様**。ただし【事実】同種が連続する箇所は第1章で3回。
- 物語との結びつき：弱い。例外は「遅延案内放送の作成（compose）」＝10:40の山場の直後に配置され、選択の帰結と同じテーマで接続している。ほかは点検→講評→評価点で閉じる。
- 「答えが文章に書いてある」問題【事実】：例「ベンチ：座面がぐらつく」「点状ブロック：一部が剥がれて浮いている」＝異常。選択肢の文面だけで判定でき、観察や推理の余地がない。
- 【提案】点検で見逃した異常を**後の場面で起こす**（見逃した券紙切れ→午後に券売機が止まる等）。業務の得点が物語の事件に直結すると、ミニゲームが「作業」から「伏線」になる。

### 2-6. 台詞の質
- 良い台詞：「私は三か月、震えてました。」（久保田、昼休み）。具体的で脆さがある。「駅の仕事は、半分が『見ること』です。」も核になる一文。
- 説明調（引用25字以内）：
  - 「…を分けて読むのが基本です」（端末の講評。システム説明）
  - 「いい点検です。異常の判断と理由が合っています。」（採点）
  - 「確認、訂正、記録。三つそろって、一つの仕事だ。」（白石、要約スローガン）
  - 「安全は、親切より先にある。」（白石、標語）
  - 「希望がそのまま通る年は、多くありません」（森下、ゲーム規則の説明）
  - 「窓口へ誘導するのも立派な案内です。」（選択直後の久保田による正解の宣言）
- 傾向【事実】：1ノードあたり平均34文字、60文字超が9件。しかし長さより**「登場人物が主題を口に出して要約する」**ことが問題。久保田の台詞が全場面で「今のは良かった／次は〜」の評価コメントになる。

## 6. 改善提案（具体案）

### 6-1. 設計原則
1. **ジレンマの作り方**：両方の選択肢に「守れる価値」と「失う価値」を置く（安全 vs 約束、規則 vs 目の前の人、正直 vs 誰かの面目）。誤答（見え見えの悪手）を削り、**4択のうち正解を1つにしない**。

  - 誤りは「持ち場ごとの小さなミス」から、**実際に1人が困る**ミスへ（行き先の誤放送＝杉浦の25年前と同型）。杉浦が過去を語るのは**押し通した場合のほうが強い**（失敗の最中に同じ痛みを知る人がいる）。正直ルートは、杉浦が**あなたを信頼して鍵を一つ預ける**（rel条件）で報いる。→ どちらのルートにも良い場面がある。
  - コーヒーの選択肢：削るか、「コーヒーで誤魔化すが、杉浦だけが見ていた」へ。
- `bf_dawn`：感想アンケートをやめ、**杉浦の「鍵を渡す相手を探している」**を全員に示し、その上で「どう答えるか」を選ばせる。(a) 引き受けたい（まだ早い）(b) 正直に断る (c) 津村さんに会わせてほしい。**引き受けたい→杉浦は期待を預け、第6章の面談で「早番の後任」という進路が現れる**。断る→杉浦は別の人を探し、**後任が現れて杉浦が去る寂しさ**が描かれる。

### 6-3. 横断的な改善
1. **rel の可視化と読み取り**：久保田・杉浦・山科・白石の4人は rel閾値で場面が変わる。例：久保田rapport≥3→「週末に自分の失敗談」、≤0→「事務的な指導」。第1〜3章で最低6箇所。
