## B. 動き（アニメーション・遷移・演出）

### 現状（コード `src/ui/styles.css`、`parts.tsx`、`GameScreen.tsx`）
【事実】
- あるもの：次へ▼の上下動（nxBob）、選択肢のフェードイン（chIn、遅延付き）、トースト、シート/モーダルの下からの出現（sheetUp）、スタンプの出現（stampIn）、文字送り（90/48/24文字/秒）と人物別の声のブリップ音、話者以外の人物を暗くして小さくする（`.who.dim`：brightness .58, scale .94）、`prefers-reduced-motion` 対応。
- ないもの：場面転換（暗転・フェード・ワイプ）、背景のカメラワーク（寄り／引き／パン）、人物の入退場、まばたき、口パク、息づかい、画面揺れ、フラッシュ、パーティクル、時間帯の色変化（会話場面）、ズーム。`.s25 .layer` の transition だけが定義され、人物・背景を動かす処理は見つかっていない。
- 話者の切替：表情はその行の `mood` だけ（smile/serious/worry/surprise/normal）。R7の全2,623行のうち mood 指定は738行（約28%）で、約72%は無表情のまま（story.json集計）。
- 3D：歩行（脚・腕のスイング）とカメラ追従。待機モーション、会話中の身振り、人物同士の視線はコード上なし（`humanoid.ts` の `walk` のみ）。

### 不足
- 「見ているだけで感情が伝わる」瞬間が無い。重要な選択や章の終わりは効果音（jingle）のみで、画面は静止している。
- 選択の前後で空気が変わらない（選んだ後に「間」「反応」がない）。

## C. 質感・グラフィック

### C-1 2Dドット絵の現状
【事実】
- 背景は `pixelScene` が実行時にcanvasで描く5種類（depot / office / records / shed / 既定のhr）。いずれも昼の青空か室内固定で、時間帯・天候・季節の変数を持たない。
- R7の2D場面の使用数（story.json集計）：hr 281、office 659、depot 179。**R7は3種類だけ**。records・shed は R8 で使用（records 9、shed 9）。
- 夕方〜夜（18時以降または6時前）のキャプションを持つ2D場面が57箇所あるが、背景は同じ3種のまま。
- 人物：64x80のドット絵を360px前後に拡大。髪型9種×（制服・肌・髪色）で別人に見せる設計（`pixel.ts` の STYLE）。表情は5種類（口・眉・目の形を差し替え）。ポーズは1種、向きも正面のみ。人物ごとの個性は髪・眼鏡・帽子・色にとどまる。
- 質感：全体に高い完成度でまとまっているが、陰影は顔の右側・あごの固定ルール。照明方向が場面と無関係。背景に光源（窓からの光・蛍光灯）の表現がなく、人物と背景が分離して見える。

### C-2 3Dの現状
【事実】
- 人物：ボックス・球・円柱を組み合わせたもの（`humanoid.ts`）。GLBテンプレート（`createHumanoidFrom`）もあるが、撮影画面ではボックス状の肩・手足で、顔の表情はなし（目は小球2つ）。
- 照明：`ACESFilmicToneMapping`、PCFSoft影、フォグと背景色は固定の青白（`renderManager.ts`）。夕方に近づくと空とフォグが橙に変わる処理はあるが、撮影した昼の画面は平板。【推測】影・環境光の対比が弱く「模型」に見える。
- テクスチャ：タイルは一様で、汚れ・反射・水たまり・ひび・ポスター等の生活感が少ない（撮影で確認：床・ビルとも繰り返し）。
- 画面左下の黒い四角はスティック背後に常にあり、原因未確認。

### C-3 Detroit水準との差
Detroitは実写級のパフォーマンスキャプチャ（微表情・視線・息）、映画的なカメラ（浅い被写界深度、レンズフレア、手持ち揺れ）、場面ごとの照明設計が核。ドット絵＋Webでは**同じ手法ではなく、同じ「効果（感情の伝達）」**を目指す。

## E. 音

### 現状（`src/engine/audio.ts` を読んだ。実際に聴いてはいない＝UNVERIFIED）
【事実：コード】
- すべてWeb Audio APIの合成。BGM 12曲（menu, hub, talk_calm, office, tense, warm, dawn, friend, mystery, night, festival, pride, depot）がチップチューン調（square/triangle波、約8小節のループ、ベース・キック・ハイハット）。
- 効果音：UI（click/confirm/cancel/notify/choice/page/save/error）、改札、ドア、足音、チャイム（接近/発車/案内）、列車走行（ノイズ＋モーター）、重要な選択と章末のジングル。会話中のブリップ音（人物ごとの声の高さ）。会話中はBGMを約0.55倍にダッキング。
- 環境音：ブラウンノイズ、ハム、道路ノイズ、風、鳥（ゾーン別：広場/コンコース/ホーム/事務室/メニュー）。
- 場面の音楽切替：`controller.musicFor()` が章ごとの節ごとに正規表現でトラックを選ぶ（ch1.delay→tense など）。R7以外は背景（shed/depot→depot、records→mystery、office→office）。
- 設定UI：全体・音楽・効果音・環境音の4スライダー、消音。「実車の録音ではありません」の注記。

### 評価（推測を含む）
- 良い点：構成が整っている。人物別のブリップ、ダッキング、字幕対応、場面別ゾーンは設計として良い。
- 問題点：（1）曲が12本で、R7の12章・約1,800ノード全体に対して少ない。（2）メロディが2〜4小節の単純ループで、聞き疲れしやすい（推測）。（3）square/triangleの単音シンセ中心で、感情の深さ・映画的な厚み（ストリングス、ピアノ、残響）がない。（4）声がない（ブリップのみ）。Detroitのような台詞の演技・間は再現できない。（5）会話場面で背景ごとの環境音（寮の夜の静けさ、雨音、事務室の空調）を出し分ける処理が見当たらない：2D場面は一律 `office` ゾーン（`updateAudioZone`）。（6）場面転換で音が切れる際、BGMは0.25秒でフェードするだけで、間・無音の演出は未実装。
- 改善案：リバーブ（ConvolverNode）、ローパス/ハイパスで「距離」と「部屋」、ピアノ・パッド音色（加算合成＋ADSR）、章ごとの主題＋バリエーション、無音の活用、雨・夜の虫・暖房・電車の遠音を会話背景に合わせて自動付与、ブリップの抑揚、重要な選択でBGMを一瞬ミュート。

## F. R8の画面の評価
撮影：`/tmp/an_ui3/r8_00〜07`（390px、第1章の冒頭〜業務の途中まで）。第1章は73ノード（line 54、choice 8、task 4）、R8の2D背景は office 49、shed 9、records 9、hr 5。mood指定は207行中32行（約15%）で、約85%は無表情。
- 良い点（事実）：背景が4種類（office, shed, records, hr）使われ、R7より場所の使い分けがある。`r8_02` のように人物を出さず窓の外だけを見せる場面があり、静けさの演出になっている。信頼や正確性の変化が「▲ 河合さんからの信頼」の小さな通知で出る（`r8_06`）。
- 問題点（事実）：
  1. 主人公（改善推進室）の胸像が長髪・私服に見える（`r8_00`）が、会話枠では誰の発言かのラベルが出ない行があり、人物の区別が弱い。
  2. 4月12日9時と14時など、時刻が違っても同じ昼の青空。サスペンス作品なのに、夕方や夜の暗い場面がなく、緊張が絵で出ない。調べ物（記録庫）の場面は背景が棚だけで「何を探しているか」が絵にない。
  3. 業務画面（`r8_07`）は「適切／不適切」ボタンの縦長リスト。文書や台帳の実物が画面にない。トーストが業務パネルの見出しに重なる。
  4. 非暴力のサスペンスという狙いに対し、音楽は `mystery` 1曲（records）と `office`（他）で、緊張感の段階がない。
- 改善案：「資料を並べる」場面で、2つの文書（版・日付・出どころ）を実物のドット絵で並べ、食い違う箇所を指でなぞる。夕方〜夜の記録庫（蛍光灯・影）。小さな手がかりの拡大演出（ズーム＋効果音）。人物の表情差分（疑い、動揺）。
- 未確認：R8の後半（選択後の分岐、業務以降）、章末画面（UNVERIFIED）。
